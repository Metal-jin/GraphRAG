# B 同学工作指引（数据 + 图谱构建）

> 本文件是 B 同学（数据 + 图谱构建）的完整工作说明，请反复对照。
> 核心依据是 [`ontology.md`](ontology.md)（本体定义）和 [`retrieval_strategies.md`](retrieval_strategies.md)（领域策略）。

---

## 一、你的任务（一句话）

把金庸小说变成**带时代维度的层次化知识图谱**，写进 Neo4j，并提供数据读取接口，供 C、D 检索使用。

---

## 二、相比之前的变化（重点看）

| 变化点 | 之前 | 现在 |
|---|---|---|
| 实体属性 | 只有 name | **每个实体加 `era` 时代属性** |
| 关系类型 | 9 个 | 9 个 + 新增 `BRANCHED_FROM`（门派演化） |
| 图谱结构 | 扁平 | **门派 → 人物 → 武功 三层层次** |
| 武功传承 | 无 | **不用额外抽三元关系**，靠"师徒 + 精通"组合推导 |

---

## 三、数据范围（方案一 + 方案二）

- **阶段一**：先用**一部《射雕英雄传》**验证流程。此时所有实体 `era` 基本是"射雕"，`era` 字段**先填上、结构预留**，暂不发挥跨书作用。
- **阶段二**：扩充到**多部小说**（《射雕》《神雕》《倚天》），`era` 真正用于跨书噪声过滤（防止把《倚天》人物错连到《射雕》）。

> 所以：**抽取代码里必须一开始就支持 `era` 字段**，哪怕阶段一暂时都填"射雕"。别到阶段二才发现代码里没这个字段、要重写。

---

## 四、具体任务（4 件事）

### 1. 找语料

- 找金庸小说 txt（阶段一先用《射雕英雄传》），放进 `data/source/`（**不提交 git**）。

### 2. 写 `corpus.py`（切块）

- 把整本书切成文本块，每块几百字，块间少量重叠。
- 这个和之前一样，没变化。

### 3. 写 `build_kg.py`（抽取 + 入库）★ 核心变化在这

- 用 LLM 抽取实体关系，**按 `docs/ontology.md` 的新要求**（重点：带 `era` 属性、层次关系）。
- 抽取 prompt 直接用下面的模板：

```
你是一个知识图谱抽取专家。请从以下金庸小说文本中提取实体和关系。

文本：
{chunk_text}

实体类型（每个实体都要带 era 时代属性，判断不了就留空）：
1. 人物：era（射雕/神雕/倚天）
2. 门派：era、location
3. 武功：type（内功/外功/轻功/暗器）
4. 地点

关系类型（方向要正确）：
- MASTER_OF（师徒）：A 是 B 的师父
- SPOUSE_OF（夫妻，双向）
- PARENT_OF（父母子女）：A 是 B 的父母
- SWORN_BROTHER_OF（结拜，双向）
- ENEMY_OF（仇敌，双向）
- BELONGS_TO（所属门派）：A 属于门派 B
- MASTERS（精通武功）：A 精通武功 B
- FOUNDER_OF（创立门派）：A 创立门派 B
- LOCATED_IN（位于地点）：A 位于地点 B
- BRANCHED_FROM（门派演化，可选）

只返回 JSON，格式：
{"entities": [{"name": "...", "type": "人物", "era": "射雕"}], "relationships": [{"source": "...", "target": "...", "type": "MASTER_OF"}]}
只返回 JSON，不要其他内容。
```

- 抽取后写入 Neo4j，实体用 `MERGE` 去重。
- 建向量索引 `text_embeddings` + 全文索引 `text_fulltext`（和之前一样）。

### 4. 写 `data_loader.py`（数据接口）★ 要支持 D 的领域策略

除了之前的 `get_chunks()`、`get_graph()`、`search_by_vector()`，**额外提供图查询能力**，让 D 的领域策略能查：

| D 需要的查询 | 说明 |
|---|---|
| 师徒链查询 | 沿 `MASTER_OF` 反向走多跳（找"师父的师父"） |
| 门派聚合查询 | 定位门派 → 聚合其下所有人物和武功 |
| 武功传承查询 | 找精通某武功的人 + 他们之间的师徒关系 |

> **最简单的做法**：`data_loader.py` 提供一个**执行 Cypher 查询的通用函数**，比如 `run_query(cypher, params)`，让 D 自己写 Cypher。这样你就不用逐个实现上面的查询了。

---

## 五、注意事项

1. **`era` 属性尽量填**：能判断时代就填（射雕/神雕/倚天），判断不了留空，别瞎填。
2. **同名实体合并**：同一个"郭靖"只能一个节点，用 `MERGE`。
3. **关系方向要对**：师徒、父母、所属、精通、创立、位于有方向；夫妻、结拜、仇敌双向。
4. **武功传承不用单独抽**：只需抽"师徒（MASTER_OF）"和"精通（MASTERS）"，传承链由 D 的检索阶段推导。
5. **`data_loader.py` 的返回格式要先和 C、D 约定好**再写（尤其是 `get_graph()` 和 `run_query()` 返回什么结构）。
