## 一、当前数据的问题（实测发现）

### 1. 师徒关系（MASTER_OF）严重错乱

查询「郭靖的师父」返回了这些**错误结果**：

- 成吉思汗（蒙古大汗，非师父）
- 黄蓉（郭靖的妻子，非师父）
- 欧阳锋（郭靖的仇敌，非师父）
- 王重阳（郭靖的**师祖**，跳代了，应该是马钰的师父）
- 尹志平（郭靖的**同门师弟**，非师父）
- 杨铁心（郭靖的义叔，非师父）
- 陆冠英、穆念慈、博尔忽（完全无关）

还出现了**循环**：「郭靖的师父的师父」里出现了「郭靖」本人。

### 2. 别名/指称被当成独立实体

图谱里出现了大量**称呼而非正名**的节点：

- 七师父、六师父、四师父、那道士、那道人、三髻道人
- 柯老恩师、洪老恩师、马道长、丘道长、丘真人、马真人
- 丹阳子马钰（应为「马钰」）、飞天蝙蝠柯镇恶（应为「柯镇恶」）
- 七公、七兄（都应是「洪七公」）、全真三子（合称，非实体）

### 3. 关系类型失控

图谱里出现了 `FATHER_OF、MOTHER_OF、KILLED_BY、LOVES、HATES、TEACHES` 等**几百种**非白名单关系，而不是约定的 10 种。

## 二、抽取 prompt 的关键约束（整改核心）

### 约束 1：师徒关系（MASTER_OF）—— 最需要收紧

在抽取 prompt 里明确写：

- **方向固定**：`师父 -[:MASTER_OF]-> 徒弟`（箭头指向徒弟）。
- **只在「明确有师徒名分或正式传过武功」时才抽 MASTER_OF**。
- **明确排除**以下关系，它们不是 MASTER_OF：
  - 夫妻 → 用 SPOUSE_OF
  - 仇敌/对手 → 用 ENEMY_OF
  - 父子/父女 → 用 PARENT_OF
  - 岳父/义父/义兄 → 不抽 MASTER_OF
  - 同门师兄弟 → 不抽 MASTER_OF
  - 师祖/太师祖 → **隔代，不直接抽 MASTER_OF**
- **一个人最多 3~5 个师父**，超过说明抽错了。
- **禁止循环**：A 的师父不能反过来又是 A 的徒弟。

### 约束 2：实体名只用「正名」

- name 一律用**正式名字**，禁止用称谓、绰号、简称。
- 反面例子（禁止）：七师父、那道士、柯老恩师、丘道长、马真人、丹阳子马钰、飞天蝙蝠柯镇恶、七公、七兄、洪老叫化。
- 正面例子：洪七公、马钰、柯镇恶、丘处机、王重阳。
- **遇到"七公/北丐/洪帮主"一律识别为「洪七公」**（用正名）。

### 约束 3：关系类型严格白名单

- 只允许 10 种：`MASTER_OF、SPOUSE_OF、PARENT_OF、SWORN_BROTHER_OF、ENEMY_OF、BELONGS_TO、MASTERS、FOUNDER_OF、LOCATED_IN、BRANCHED_FROM`。
- 把 `FATHER_OF/MOTHER_OF/SON_OF/DAUGHTER_OF` 统一为 `PARENT_OF`。
- 把 `HUSBAND_OF/WIFE_OF` 统一为 `SPOUSE_OF`。
- 其余自造类型（KILLED_BY、LOVES 等）一律丢弃。

## 三、后处理（抽取后可加代码兜底）

1. **实体对齐**：`entity_alignment.py` 已有「相似度层」，能自动发现「丹阳子马钰→马钰」这类别名，建议审核后落库（当前只写 CSV 没落库）。
