# 金庸武侠知识图谱本体（ontology）

> 本文件定义：我们从金庸小说文本里**抽取哪些实体类型**和**关系类型**。
> 这是 B 同学写抽取逻辑（build_kg.py）的依据，也是 C、D 检索、E1 评测的基础。
> 初版由组长提供，B 同学负责最终定稿。**改动必须通知全组。**
>
> 本体的核心特色是 **时代维度 + 门派→人物→武功 的层次结构**，
> 这是支撑"跨代际关系追溯"和"武功传承推理"的基础。

---

## 一、实体类型（Entity Types，带时代维度）

每个实体都有一个 `era` 属性，标记其所属时代。

| 中文标签 | 说明 | 关键属性 | 例子 |
|---|---|---|---|
| 人物 | 小说中的角色 | `name`、`era` | 郭靖（era=射雕）、杨过（era=神雕） |
| 门派 | 武林门派/组织 | `name`、`era`、`location` | 全真教（era=射雕）、峨眉派（era=倚天） |
| 武功 | 武功招式/秘籍 | `name`、`type`、`era` | 降龙十八掌、九阴真经 |
| 地点 | 地名/场所 | `name` | 襄阳、桃花岛、终南山 |

### 时代维度（era）取值

| era 值 | 对应时代 | 代表作 |
|---|---|---|
| `射雕` | 南宋 | 《射雕英雄传》 |
| `神雕` | 南宋末-元初 | 《神雕侠侣》 |
| `倚天` | 元末明初 | 《倚天屠龙记》 |

> **时代维度是本体的最大差异化点**：它让我们能回答"南宋时期丐帮帮主有哪些"这类时间约束问题，这是扁平图谱无法处理的。

## 二、层次结构（核心设计）

本体不是扁平的，而是**三层层次结构**：

```
门派（Sect）
  │ BELONGS_TO（人物属于门派）
  ▼
人物（Character）
  │ MASTERS（人物精通武功）
  ▼
武功（MartialArt）
```

- **门派层**：组织归属（谁属于哪个门派）
- **人物层**：人际关系（师徒、夫妻、父母、结拜、仇敌）
- **武功层**：技能传承（谁精通什么武功、武功从哪来）

---

## 三、关系类型（Relationship Types）

关系类型用英文大写命名（Neo4j 惯例）。**方向约定见每条的说明。**

### 人际关系

| 关系类型 | 含义 | 方向说明 | 例子 |
|---|---|---|---|
| `MASTER_OF` | 师徒 | A 是 B 的师父：`(A)-[:MASTER_OF]->(B)` | 洪七公 → 郭靖 |
| `SPOUSE_OF` | 夫妻 | 双向 | 郭靖 ↔ 黄蓉 |
| `PARENT_OF` | 父母子女 | A 是 B 的父母：`(A)-[:PARENT_OF]->(B)` | 黄药师 → 黄蓉 |
| `SWORN_BROTHER_OF` | 结拜 | 双向 | 郭靖 ↔ 周伯通 |
| `ENEMY_OF` | 仇敌 | 双向 | 郭靖 ↔ 欧阳锋 |

### 层次关系（门派/武功归属）

| 关系类型 | 含义 | 方向说明 | 例子 |
|---|---|---|---|
| `BELONGS_TO` | 所属门派 | A 属于门派 B：`(A)-[:BELONGS_TO]->(B)` | 郭靖 → 丐帮 |
| `MASTERS` | 精通武功 | A 精通武功 B：`(A)-[:MASTERS]->(B)` | 郭靖 → 降龙十八掌 |
| `FOUNDER_OF` | 创立门派 | A 创立门派 B：`(A)-[:FOUNDER_OF]->(B)` | 王重阳 → 全真教 |
| `LOCATED_IN` | 位于地点 | A 位于地点 B：`(A)-[:LOCATED_IN]->(B)` | 桃花岛 → 东海 |

### 演化关系（新增，体现传承/演化）

| 关系类型 | 含义 | 方向说明 | 例子 |
|---|---|---|---|
| `BRANCHED_FROM` | 门派演化 | B 门派由 A 衍生：`(B)-[:BRANCHED_FROM]->(A)` | 峨眉派 → 郭襄（郭襄所创，源自桃花岛/全真体系） |

## 四、武功传承的推导（不用专门的三元关系）

武功传承链可以通过**两个已有关系的组合**推导出来，不需要额外的三元关系：

```
洪七公 -[:MASTER_OF]-> 郭靖       （师徒）
洪七公 -[:MASTERS]-> 降龙十八掌   （精通）
郭靖   -[:MASTERS]-> 降龙十八掌   （精通）

→ 推导出：降龙十八掌 从 洪七公 传到 郭靖
```

**好处**：抽取时只需抽"师徒"和"精通"两种简单关系，传承链由检索阶段自动推导，降低抽取难度。

## 五、抽取示例

假设文本片段是：

> "南宋时期，洪七公是丐帮帮主，他将降龙十八掌传授给郭靖。郭靖后来娶了黄蓉，黄蓉是黄药师的女儿。"

抽取结果应该是：

**实体**（注意带 `era` 属性）：
```json
[
  {"name": "洪七公", "type": "人物", "era": "射雕"},
  {"name": "郭靖", "type": "人物", "era": "射雕"},
  {"name": "黄蓉", "type": "人物", "era": "射雕"},
  {"name": "黄药师", "type": "人物", "era": "射雕"},
  {"name": "丐帮", "type": "门派", "era": "射雕"},
  {"name": "降龙十八掌", "type": "武功"}
]
```

**关系**：
```json
[
  {"source": "洪七公", "target": "郭靖", "type": "MASTER_OF"},
  {"source": "洪七公", "target": "丐帮", "type": "BELONGS_TO"},
  {"source": "郭靖", "target": "降龙十八掌", "type": "MASTERS"},
  {"source": "洪七公", "target": "降龙十八掌", "type": "MASTERS"},
  {"source": "郭靖", "target": "黄蓉", "type": "SPOUSE_OF"},
  {"source": "黄药师", "target": "黄蓉", "type": "PARENT_OF"}
]
```

## 六、注意事项

1. **只抽上面定义的实体类型和关系类型**，不在清单里的不要抽（保证图谱规范）。
2. **同名实体要合并**：同一个"郭靖"只能有一个节点，抽取时用 `MERGE` 合并。
3. **关系方向要对**：师徒、父母、所属、精通、创立、位于都有方向；夫妻、结拜、仇敌是双向。
4. **实体名要规范**：用全称，不要用昵称简称（除非文本里只出现简称）。
5. **`era` 属性尽量填**：能判断时代就填（射雕/神雕/倚天），判断不了可留空，不要瞎填。
