## 2. 本轮新增：证据约束与 PARENT_OF 二次校验

### 2.1 提示词（extract-v5）

在原有要求上增加硬性约束：

- 只抽取原文**明确写出**的关系，不得因"同时出现 / 同门派 / 互相认识"推断；
- 每条关系必须带 `evidence` 字段：原文中**逐字**支持该关系的一句话；
- PARENT_OF 必须原文有 父/母/爹/娘/儿子/女儿/之子/之女/所生/生下 等表述。

### 2.2 代码侧二次校验（`src/ingest/relation_evidence.py`）

```
gate_relationships(relationships, chunk_text):
  1) 有 evidence → 必须是文本块的逐字子串，否则拒绝（防编造/改写）
  2) PARENT_OF 额外要求 evidence 命中亲属词表，否则拒绝
  3) 无 evidence → 退化为"同一句共现"；PARENT_OF 仍要求共现句含亲属表述
```

被拒关系写入 `rejected` 清单并附原因，可审计。

效果：上一轮（v4）有 66% 的 PARENT_OF 证据句不含亲属词；本轮全部关系都必须有原文证据，
PARENT_OF 数量从 397 降到 258，且每条都能回到原文。

代价：关系总量从 8,030 降到 3,670（**-54%**），MASTER_OF 从 625 降到 318 —— 这是
"精确率换召回率"的取舍，直接体现在多跳师徒题（0/4）。

## 5. 如何解读

1. **领域策略的低分主要是问法不匹配**：54 题里"门派"多为「洪七公属于哪个门派」这类
   人物→门派问法，`sect_agg` 需要门派作起点，只能返回 `no_entity`；这类题由分类器
   交给 `vector`（general 83.33% 即来自此）。**63% 的自动路由才是系统真实水平。**
2. **证据约束是精确率/召回率取舍**：关系总量减半，换来 99.97% 的证据可追溯。
   后续的关系计划、人物指称消歧与门派路由把多跳题补了回来：
   自动路由 63% → 77% → 84% → **88%**，多跳师徒 0/4 → **4/4**，多跳亲属 2/8 → **8/8**，
   多跳属性 2/4 → **4/4**，多跳婚姻 2/3 → **3/3**。
3. **全部旧数字已作废**：仓库中不再保留任何旧评测数字，`output/` 下三个文件
   （`compare_table.md`、`compare_results.json`、`auto_route_*`、`injection_experiment.json`）
   均为本轮重新生成。

## 6. 数据质量与后续建议

1. **多跳师徒 0/4**：MASTER_OF 从 625 降到 318，是证据约束的直接结果。
   若要多跳题更稳，可对师徒关系放宽到"同句共现 + 师承词"而不要求逐字证据句。
2. **PARENT_OF 仍有噪声**：258 条里抽样仍有少量错误（如把同段共现当亲属），
   但错误率已明显低于上一轮。
3. **别名归一**：本轮归并 70 个节点（消灭了"蓉儿/七公/一灯"等重复），
   仍有 `郭靖之父` 类指称节点（已从实体链接中过滤，不参与匹配）。
