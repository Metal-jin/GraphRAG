## 3. 结论与解读

1. **自动路由 88%** 是系统真实水平：分类器把"人物→门派""人物→属性"等问法交给
   `vector`（general 类 84.62%），人物关系交给 `person_relation`（96.97%），
   门派问法交给 `sect_agg`（3/3），多跳亲属/师徒/属性/婚姻题全部答对。
2. **单方法表格的低分不代表实现失败**：`sect_agg` 需要门派作起点，
   在 54 题的"X 属于哪个门派"问法上只能返回 `no_entity`；这是**问法不匹配**，
   不是检索逻辑错误。评估领域策略应看分类别/适用题型，而不是一张总表。
3. **证据约束的取舍**：v5 要求每条关系有原文证据句，关系总量 8,030 → 3,670，
   换来 99.97% 的可追溯率；自动路由 60% → 63%，但多跳师徒（0/4）召回下降。
4. **vector 与 library_graphrag 接近**（74.07% vs 75.93%），1 跳图扩展在单跳事实题上
   没有明显增益。
5. **person_relation 大幅提升**（单独跑 40.74%，路由后 96.97%）：新的关系计划与
   人物指称消歧让多跳亲属（8/8）、多跳师徒（4/4）、多跳属性（4/4）、
   多跳婚姻（3/3）全部答对。

## 4. 误差分析（人工抽查方向）

| 错误类型 | 说明 | 现状 |
|---|---|---|
| 实体未召回 | 问题中的关键人物没进检索结果 | 多跳题主要来源 |
| 关系方向错误 | 如把"父亲"答成"儿子" | 本体无性别属性，只能靠原文 |
| 多跳中断 | 第一跳正确、第二跳无关系 | MASTER_OF 覆盖不足 |
| 生成幻觉 | 上下文没有该事实 | thinking 关闭后明显减少 |
| 图谱抽取错误 | 共现被当成关系 | 证据闸门后大幅减少 |
