# GraphRAG 评测报告

> 本文档是 E1 提供的评测报告模板。真实实验完成后，请用 `python -m src.eval.run_compare` 更新 `output/compare_table.md`，再把汇总数字和分析填写到本文档。

## 1. 实验目的

在相同问题集、相同 `top_k` 和相同生成配置下，比较纯向量检索、调库图检索、PathRAG 和 TCPR 四种方法回答金庸知识图谱问题的能力，重点观察：

1. 图结构是否帮助方法回答两跳及以上问题；
2. 类型约束和关系加权是否能够减少错误实体；
3. 不同方法在准确性、实体召回和响应速度之间的取舍。

## 2. 实验设置

| 项目 | 设置 |
|---|---|
| 问题集 | `src/eval/questions.json`，50 题 |
| 题型 | 亲属、师徒、婚姻、门派、结拜、武功 |
| 多跳题 | 10 题，字段 `hop=2` |
| 方法 | vector / library_graphrag / pathrag / tcpr |
| top_k | 运行命令中的统一值，默认 5 |
| 自动评分 | 命中 `acceptable_answers` 中任一实体或别名 |

## 4. 多跳问题分析

自动脚本当前按题目记录逐题结果；建议从 `output/compare_results.json` 中筛选 `questions` 里 `hop=2` 的题目，单独统计四种方法。需要回答：

- 哪种方法的两跳实体命中率最高？
- 错误主要发生在第一跳找不到实体，还是第二跳关系方向错误？
- TCPR 的类型约束是否减少了“人物—门派”“人物—武功”等类型混淆？

## 5. 误差分析

自动命中不是完整事实正确性。例如回答同时提到正确人物和错误人物时，字符串规则仍可能判为命中。因此应从 `compare_results.json` 选取：

- 每种方法至少 3 个正确样例；
- 每种方法至少 3 个错误样例；
- 至少 3 个多跳问题；

人工检查 `answer_text`、`evidence`、`raw_context` 和 `debug_info`，并按以下原因归类：

| 错误类型 | 说明 | 数量 |
|---|---|---:|
| 实体未召回 | 问题中的关键人物没有进入检索结果 | 待填写 |
| 关系方向错误 | 例如把“父亲”回答成“儿子” | 待填写 |
| 多跳中断 | 第一跳正确，但第二跳没有继续推理 | 待填写 |
| 生成幻觉 | 上下文没有该事实，但答案自行编造 | 待填写 |
| 其他 | 语料缺失、图谱抽取错误等 | 待填写 |

## 7. 可复现实验命令

```bash
python -m src.eval.run_compare \
  --methods vector library_graphrag pathrag tcpr \
  --top-k 5 \
  --output output/compare_table.md \
  --result-json output/compare_results.json
```

如果某个方法还未安装或未注册，脚本会把它记录为 `error`，并继续生成其他方法的结果；正式答辩前应确认四个方法的可用率都达到 100%，或者在报告中说明失败原因。
