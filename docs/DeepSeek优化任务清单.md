### 01.【P1】落实 1500/200 切块方案，保证文本覆盖与参数合法

**位置**：`src/ingest/corpus.py`、`tests/test_kg_builder.py`。

**现状**：默认参数已改成 1500/200，仍是按字符固定滑窗。缺少 `size > 0`、`0 <= overlap < size` 校验；无效步长可能导致循环不前进。函数和 CLI 需要使用同一套校验。

**修改要求**：

- 保留 1500/200 为默认值，并允许显式覆盖。
- 优先在同一章节内沿段落、完整句子切分，明确 1500 是目标长度还是硬上限；如允许有限超长，需要文档和上限约束。

**验收**：默认配置、短章、长章、无标点文本、章节边界、无效参数均有合理行为；移除重叠后能按偏移还原原文。

### 02.【P1】切块、图谱、向量索引与 checkpoint 必须版本一致

**位置**：`src/ingest/corpus.py`、`src/ingest/build_kg.py`、`src/ingest/data_loader.py`、`scripts/build_kg.ps1`。

**问题**：目前 `chunk_id` 为“书名::序号”，checkpoint 只保存这些 ID。切块从 600/80 改成 1500/200 后，相同 ID 对应不同正文，旧断点可能跳过新内容；旧实体关系和 MENTIONS 也不会因正文覆盖而自动撤销。

**修改要求**：

- 为数据集建立 manifest，记录原文指纹、切块算法和参数、抽取模型/提示词版本、嵌入版本。
- chunk 身份包含数据版本与来源偏移，或使用等效的稳定且可验证方案；将内容哈希与逻辑 ID 分开管理。
- checkpoint 绑定数据版本和目标数据库/命名空间，发现不兼容时明确拒绝 resume。
- 准备隔离的新数据版本与迁移脚本，完成验证后再切换读取；保留旧版本回退能力。
- 迁移必须覆盖旧 Chunk、MENTIONS、关系来源和向量索引的处理，不能只换切块 JSON。

**验收**：600/80 的旧断点不能静默用于 1500/200；新旧数据可区分，重复导入幂等，失败后可恢复。

### 03.【P1，已复现】统一嵌入算法，消除跨进程不确定性

**位置**：`src/ingest/build_kg.py::hash_embed/make_embedder`、`src/retrieve/vector_utils.py::_hash_embedding/Embedder`、`src/ingest/data_loader.py`。

**问题**：入库哈希用内置 `hash(ch)`，受 Python 哈希种子影响；离线检索用 SHA256、有符号投票和另一套分词逻辑。两个实现虽然都是 256 维，向量语义并不一致。两个不同 `PYTHONHASHSEED` 的进程生成同一句话向量已经验证不一致。

**修改要求**：抽取、建索引、在线查询、离线检索统一调用一个嵌入模块；本地哈希使用稳定算法；记录算法标识、分词/预处理版本和维度。哈希仅作为可复现的词法兜底，真实语义检索使用适合中文的语义嵌入方案，并通过实验选择。

**验收**：不同进程、不同哈希种子下同文同向量；入库与查询一致。明确旧向量需要重新生成，不能仅修改函数后继续沿用旧索引。

### 04.【P1】远程嵌入失败时不得混用不兼容向量

**位置**：`src/retrieve/vector_utils.py::Embedder.embed/search_chunks`、`src/ingest/build_kg.py::make_embedder/ensure_indexes`。

**问题**：远程嵌入异常会按单条文本退回本地哈希；同一次检索中的查询和候选可能来自不同模型或不同维度。维度不一致目前直接给相似度 0，容易隐藏配置错误。索引仅 `IF NOT EXISTS`，没有验证已有索引的模型与维度。

**修改要求**：一批数据使用一致模型；失败时明确失败，或整批进入独立的兼容兜底流程。校验维度、数值合法性、模型版本和索引状态；复用客户端、支持批量请求与按内容哈希缓存，避免每次查询重新嵌入全部文本块。

**验收**：模拟远程部分失败、维度变更、模型变更时，结果不会静默混用向量；缓存有版本隔离。
