# 领域检索策略设计（retrieval_strategies.md）

> 本文档由 D 负责，定义三个**领域专用检索策略**的设计。
> 它们与 C 的两个基线（vector / library_graphrag）并列，通过统一 `QAMethod` 接口接入系统，用同一套问题集对比。

---

## 一、设计背景：为什么是"领域策略"而非"通用方法对比"

武侠知识图谱有强烈的领域结构（门派 → 人物 → 武功 的层次、师徒代际、武功传承）。通用图检索（如调库的 VectorCypherRetriever）不理解这些结构，只能做"找相似 + 扩展 2 跳"这种通用操作。

领域策略的价值在于：**针对武侠特有的问题类型，设计专门的图遍历方式**，从而在跨代际追溯、门派聚合、武功传承这类问题上，比通用方法更准、更可解释。

---

## 二、策略总览

| 方法名 | 类型 | 负责 | 解决什么问题 |
|---|---|---|---|
| `vector` | 基线 | C | 纯向量检索，不用图 |
| `library_graphrag` | 基线 | C | 调库的通用图检索 |
| `master_chain` | 领域策略 | D | 师徒链追溯 |
| `sect_agg` | 领域策略 | D | 门派聚合 |
| `art_lineage` | 领域策略 | D | 武功传承 |

对比逻辑：**两个通用基线 vs 三个领域策略**，看领域策略在对应类型的问题上是否更准。

---

## 三、各策略详细设计

### 策略 1：师徒链检索（master_chain）

**解决的问题**：跨代际师徒关系，如"郭靖的师父的师父是谁"。

**算法流程**：
1. 从问题中识别起始人物（用向量检索或实体匹配定位到图谱节点）。
2. 沿 `MASTER_OF` 关系**反向**走多跳（1~3 跳），收集整条师徒链。
3. 把师徒链整理成"路径"形式作为证据。

**Cypher 示意**：
```cypher
MATCH (p:人物 {name: '郭靖'})<-[:MASTER_OF*1..3]-(master:人物)
RETURN master.name AS name, length((p)<-[:MASTER_OF*1..3]-(master)) AS depth
```

**知识注入形式**：关系路径（`郭靖 ← 洪七公 ← 未知`）。

---

### 策略 2：门派聚合检索（sect_agg）

**解决的问题**：门派归属与聚合，如"丐帮有哪些绝学""全真教有哪些人物"。

**算法流程**：
1. 定位门派节点。
2. 沿 `BELONGS_TO` 反向聚合该门派下的所有人物。
3. 再沿 `MASTERS` 聚合这些人物精通的武功。
4. 整理成"门派 → 人物 → 武功"的子图。

**Cypher 示意**：
```cypher
MATCH (s:门派 {name: '丐帮'})<-[:BELONGS_TO]-(p:人物)
OPTIONAL MATCH (p)-[:MASTERS]->(a:武功)
RETURN p.name AS person, collect(a.name) AS arts
```

**知识注入形式**：子图摘要（门派下的人物清单 + 武功清单）。

---

### 策略 3：武功传承检索（art_lineage）

**解决的问题**：武功传承链，如"降龙十八掌从谁传到谁"。

**算法流程**：
1. 定位武功节点。
2. 找到所有精通该武功的人物（沿 `MASTERS` 反向）。
3. 在这些人之间查找 `MASTER_OF` 关系，推导出"武功从师父传给徒弟"的传承链。

**Cypher 示意**：
```cypher
MATCH (a:武功 {name: '降龙十八掌'})<-[:MASTERS]-(master:人物)-[:MASTER_OF]->(disciple:人物)
WHERE (disciple)-[:MASTERS]->(a)
RETURN master.name AS 从谁, disciple.name AS 传给谁
```

**知识注入形式**：传承路径（`降龙十八掌：洪七公 → 郭靖`）。

## 四、与基线的对比关系

| 维度 | 通用基线（vector / library_graphrag） | 领域策略（master_chain 等） |
|---|---|---|
| 理解领域结构？ | 否（通用相似度/扩展） | 是（师徒/门派/传承） |
| 跨代际追溯 | 弱（扩展易引入噪声） | 强（定向走 MASTER_OF） |
| 可解释性 | 低（"检索到了这些块"） | 高（"沿着师徒链得到答案"） |
| 时间约束 | 无法处理 | 可用 era 过滤 |

**评测预期结论**：领域策略在"人物关系/门派归属/武功传承"类问题上准确率更高、证据更可解释；通用基线在简单事实问题上够用。

---

## 五、实现要点

1. **统一接口**：三个策略都实现 `QAMethod`，用 `@register(name)` 注册，返回统一 `Answer`。
2. **复用底层工具**：向量检索用 C 的 `vector_utils.py`（用于定位起始实体）；图查询用 B 的 `data_loader.py`。
3. **证据可解释**：每个策略的 `Answer.evidence` 要带上"路径"或"子图"，供前端高亮展示。
4. **`era` 过滤（可选增强）**：如果问题涉及时代（如"南宋时期"），先用 `era` 过滤，再走领域策略。
